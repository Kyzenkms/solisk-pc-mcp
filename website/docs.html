Install on Windows

  1. Download the latest beta installer from GitHub Releases.
  2. Run PC Control MCP Setup 1.0.0-beta.exe.
  3. Windows SmartScreen may warn because the beta installer is unsigned. Verify the release checksum before continuing.
  4. Complete onboarding and keep the generated owner API key private.
Beta software can control files, processes, input, and system functions. Test with non-critical data and minimum permissions.

Choose connection mode

Mode Use when Address
Solisk hosted You need a stable public URL without managing a server. https://mcp.solisk.org/mcp/device-id
Self-hosted You operate your own relay and domain. https://mcp.example.com/mcp/device-id
Local only Client runs on the same PC. http://localhost:3000/mcp

Current desktop beta presents Hosted and Local during first-run onboarding. Custom self-hosted relay details can be configured in Settings; dedicated onboarding is planned.

Connect an MCP client

Use the MCP URL shown in Dashboard and owner or scoped API key from Settings.

HTTP configuration

{
  "mcpServers": {
    "pc-control": {
      "type": "url",
      "url": "https://mcp.solisk.org/mcp/workspace-id",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}

Never paste the owner key into public issues, screenshots, repositories, or shared chat transcripts. Create a scoped key for routine clients.

Set permissions before tools

Approval mode

Always ask requires local confirmation for tool execution. Automatic modes reduce friction but increase risk if a client or prompt is compromised.

Allowed paths

Restrict file operations to directories the AI actually needs. Blank allowed paths mean broad filesystem access, subject to explicit denied paths.

Scoped keys

Create separate credentials for file reading, shell access, screenshots, input control, or administration. Revoke a key instead of sharing the owner credential.

Self-host the relay

The separate self-hosted repository includes one Linux VPS installer with OS detection, Docker Compose, and optional Caddy HTTPS. 

bash -c "$(curl -fsSL https://raw.githubusercontent.com/Kyzenkms/solisk-mcp/master/self-hosted-setup/vps/install.sh)"

Supported families include Debian/Ubuntu, Fedora/RHEL, Rocky/Alma, Amazon Linux, Alpine, Arch/Manjaro, and openSUSE/SUSE. A real domain requires DNS pointing to the VPS and inbound ports 80/443.

For a same-PC relay, use the Windows local setup script from the self-hosted repository. Local mode is not public unless you deliberately add a tunnel or expose ports.

Troubleshooting

Dashboard shows old domain

Open Settings and verify the relay domain. Existing profiles can retain an older explicit hostname because defaults do not overwrite user configuration.

Browser returns 405

Expected for a normal GET request to an MCP endpoint. MCP clients send POST requests with protocol payloads.

Relay is offline

Check network access, API key, device identity, system time, and whether another machine is already claiming the same self-hosted room.

Certificate fails

Confirm DNS resolves to the relay VPS and ports 80/443 are open. For Caddy deployments, inspect docker compose logs caddy.
