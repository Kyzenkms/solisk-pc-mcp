The MCP request path

What actually happens after you connect.

PC Control MCP does not give an AI a hidden desktop session. The client speaks MCP, the server advertises tools, policy decides what can run, and the Windows process returns a structured result.

01

Configure

Add the Streamable HTTP endpoint and bearer key to Claude, ChatGPT, Cursor, or another MCP client. 

"url": "https://mcp.solisk.org/mcp/workspace-id"
"Authorization": "Bearer …"
02

Discover

The client initializes an MCP session and calls tools/list to learn which capabilities are available. 

{ "method": "tools/list" }
→ read_file, run_command, take_screenshot
03

Request

The model selects a tool and sends typed arguments. The local runtime checks key scope, paths, and approval mode. 

{ "name": "read_file",
  "arguments": { "path": "README.md" } }
04

Execute or deny

An allowed call runs on Windows and returns a JSON-RPC result. A denied or unapproved call returns an error without execution. 

{ "content": [{ "type": "text",
  "text": "…file contents…" }] }
Important: tool calls can change the machine. Start with local-only mode, approval enabled, restricted paths, and scoped keys.

Choose your boundary

One runtime. Three ways to connect.

Use managed infrastructure, bring your own relay, or keep everything on loopback. Core PC control remains local in every mode.

01 / MANAGED

Solisk hosted

Stable public HTTPS URL without router configuration or VPS maintenance.

  • mcp.solisk.org endpoint
  • Outbound desktop connection
  • Recommended for beta users
02 / OWNED

Self-hosted

Run the relay on your Linux VPS with Docker and automatic Caddy certificates.

  • Your domain and server
  • Cross-distribution installer
  • Persistent relay state
03 / OFFLINE

Local only

Use MCP clients on the same computer without public infrastructure.

  • localhost:3000
  • No relay or cloud account
  • Best for private workflows
Control is explicit

Power without invisible permission.

PC access is dangerous when authority is vague. PC Control MCP makes credentials, scopes, filesystem boundaries, and approval mode visible.

Read security model
01

Authenticate every client

Owner and scoped keys are presented as bearer credentials. Relay stores salted hashes instead of plaintext keys.

02

Grant only required tools

Scoped keys constrain categories such as file read, shell, input, system, network, and screenshots.

03

Keep execution on your machine

The desktop runtime executes tools locally. Hosted relay transports authenticated MCP requests; it is not the computer-control runtime.

04

Revoke identity when needed

Regenerating a device URL removes the old relay room, disconnects active sessions, and creates a new device identity.
